# Iranian Market Intelligence Engine — تحلیلگر خودکار بورس تهران

سیستمی که داده‌های **TSETMC** و **CODAL** را جمع‌آوری می‌کند، از آن‌ها ویژگی‌های تابلوخوانی، تکنیکال و بنیادی می‌سازد، با امتیازدهی قابل‌تنظیم و مدل آماری ارزیابی می‌کند و نتیجه را به‌صورت متن فارسی شبیه یک تحلیلگر، از طریق **Cloudflare Worker** در **ربات تلگرام** ارائه می‌دهد.

> ⚠️ این پروژه «ربات سیگنال» نیست. خروجی‌ها توصیه خرید یا فروش نیستند. داده مشاهده‌شده و تفسیر مدل جدا نمایش داده می‌شوند، و عدد «احتمال» فقط برای مدلی نشان داده می‌شود که calibration آن روی داده تاریخی تأیید شده باشد (در حال حاضر هیچ مدلی این آزمون را پاس نکرده است).

- معماری و تصمیم‌های فنی: [ARCHITECTURE.md](ARCHITECTURE.md)
- گزارش مرحله‌به‌مرحله (پیاده‌سازی، تست، مشکلات): [docs/PHASE_LOG.md](docs/PHASE_LOG.md)
- استقرار Worker و ربات: [worker/README.md](worker/README.md)

## چه داده‌ای جمع می‌شود

### از TSETMC — با کتابخانه [`tsetmc`](https://github.com/5j9/tsetmc) (5j9)

| جدول | محتوا | تناوب |
|---|---|---|
| `instruments` | نماد، نام، ISIN، بازار، تابلو، صنعت، تعداد سهام، EPS | هر snapshot |
| `intraday_snapshots` | قیمت‌ها، حجم/ارزش/تعداد تجمعی، حقیقی/حقوقی (حجم و تعداد)، **صف خرید و فروش ۵ سطحی** (قیمت، حجم، تعداد سفارش) | هر ۲ دقیقه در ساعات بازار |
| `daily_prices` | اولین، بیشترین، کمترین، پایانی، آخرین، دیروز، حجم، ارزش، تعداد، **قیمت تعدیل‌شده** | روزانه ۱۹:۰۰ (+ ردیف موقت پایان جلسه) |
| `daily_client_type` | خرید/فروش حقیقی و حقوقی: حجم، **ارزش**، تعداد | روزانه |
| `market_snapshots` | شاخص کل، ارزش و حجم معاملات بورس/فرابورس | هر snapshot |

### از CODAL — کلاینت اختصاصی + مدل `DataSource` از [`codalpy`](https://github.com/yghaderi/codalpy)

| جدول | محتوا |
|---|---|
| `codal_letters` | همه اطلاعیه‌ها: شماره پیگیری، نماد، عنوان، زمان انتشار، لینک‌ها، **نوع گزارش** و **برچسب رویداد** (افزایش سرمایه، مجمع، افشای بااهمیت، قرارداد، توقف/تعلیق، حسابرس، اصلاحیه، …) |
| `financial_statements` | صورت سود و زیان، ترازنامه، جریان وجوه نقد و فروش ماهانه؛ هر ردیف هم **`raw_data`** (داده خام کامل) دارد و هم **`normalized_data`** (اقلام استاندارد) |

### کدال را چطور می‌خوانیم؟ (PDF یا Excel؟)

**هیچ‌کدام.** صفحه HTML هر گزارش در کدال یک شیء JSON به نام `var datasource` دارد که **همان جدول‌های رسمی گزارش** را با مقدار هر سلول، تاریخ دوره و وضعیت حسابرسی در خود دارد. سیستم همین را می‌خواند:

- **دقیق‌تر از PDF است:** نیازی به تشخیص متن یا OCR نیست.
- **ساده‌تر از Excel است:** نیازی به دانلود فایل نیست.
- **مقادیر همان اعداد گزارش‌اند**، به **میلیون ریال**.
- **داده خام هم ذخیره می‌شود،** تا اگر نگاشت اقلام اشتباه بود بدون دانلود دوباره قابل اصلاح باشد.

از هر صورت مالی این‌ها استخراج می‌شود:
- **سود و زیان:** درآمد، بهای تمام‌شده، سود ناخالص، سود عملیاتی، سود خالص، EPS، سرمایه.
- **ترازنامه:** دارایی‌ها، بدهی‌ها، حقوق مالکانه، وجه نقد، تسهیلات.
- **جریان وجوه نقد:** جریان نقد عملیاتی، مخارج سرمایه‌ای، سود پرداختی.
- **دوره مقایسه:** برای هر قلم، **ستون دوره مشابه سال قبل** و **سال مالی قبل** هم ذخیره می‌شود. با همین‌ها رشد سالانه و سود ۱۲ ماه اخیر (TTM) و P/E حساب می‌شود.

از گزارش ماهانه: فروش همان ماه، فروش از ابتدای سال، و فروش مدت مشابه سال قبل.

**چیزهایی که (هنوز) خوانده نمی‌شوند:**
- **پیوست‌های PDF** مثل گزارش حسابرس و گزارش تفسیری. فعلاً فقط **عنوان** اطلاعیه برچسب‌گذاری می‌شود.
- **صورت‌های مالی تلفیقی سالانه‌ای که `datasource` ندارند.** این‌ها رد می‌شوند و حدس زده نمی‌شوند.
- **قالب‌های گزارش ماهانه‌ای که هنوز پشتیبانی نمی‌شوند** (حدود ۱۵٪ گزارش‌های ماهانه):
  - شرکت‌های خدماتی («خدمات و فروش»)،
  - بخشی از گزارش‌های بانکی،
  - بیمه و لیزینگ («فرم درآمدهای عملیاتی ماهانه»)،
  - «عملکرد ماهانه».
- **EPS و سود عملیاتی بانک‌ها** در نگاشت فعلی اقلام پیدا نمی‌شوند.
- در همه این موارد مقدار «داده در دسترس نیست» ثبت می‌شود، نه عدد ساختگی.

### محدودیت نرخ کدال

- **جستجو مسدود می‌شود:** `search.codal.ir` بعد از حدود ۳۰ صفحه جستجو IP را برای حدود ۳۵ دقیقه مسدود می‌کند (HTTP 429)، حتی با یک درخواست در هر ۵ ثانیه.
- **صفحه‌های گزارش مسدود نمی‌شوند:** `www.codal.ir` چنین محدودیتی نشان نداده است.
- **راه‌حل:**
  - هر صفحه جستجو فوراً ذخیره می‌شود.
  - پیشرفت در `data/codal_bootstrap_state.json` ثبت می‌شود و اجرای دوباره از همان‌جا ادامه می‌دهد.
  - پردازش گزارش‌ها موازی با جستجو انجام می‌شود.

بارگیری کامل **فقط یک بار** لازم است. بعد از آن، کار ۱۵دقیقه‌ای فقط اطلاعیه‌های جدید را می‌گیرد و خاموشی لپ‌تاپ را هم جبران می‌کند.

## ویژگی‌ها و تحلیل

| موتور | نمونه ویژگی‌ها |
|---|---|
| **تابلو** | نسبت حجم ۵/۲۰/۳۰ روزه، z-score حجم، پول حقیقی و نسبت آن، پول حقیقی تجمعی ۵/۲۰ روزه، قدرت خریدار و روند آن، اندازه معاملات، شکاف قیمت، فاصله از سقف/کف روز، مومنتوم |
| **صف و سفارش‌ها** | عدم‌تعادل عرضه/تقاضا، اسپرد، تمرکز سفارش، تشخیص صف خرید/فروش و قدرت صف |
| **درون‌روزی** | تغییر ۵/۱۵/۳۰ دقیقه‌ای قدرت خریدار، حجم، قیمت، پول حقیقی؛ رژیم «افزایشی/کاهشی/ثابت/ناگهانی» |
| **تکنیکال** (روی قیمت تعدیل‌شده) | SMA/EMA، RSI، MACD، ATR، بولینگر، حمایت/مقاومت ۲۰ و ۶۰ روزه، شکست، روند، نوسان‌پذیری |
| **بنیادی** | رشد درآمد/سود/EPS، حاشیه‌ها، TTM، P/E، P/S، P/B، اهرم، جریان نقد، رشد فروش ماهانه/فصلی/تجمعی، پرچم رویدادها |
| **بازار** | درصد سهم‌های مثبت، میانه بازده، برآیند پول حقیقی کل بازار |

همه ویژگی‌ها فقط از داده‌ای ساخته می‌شوند که تا همان لحظه منتشر شده بود (یک تست مخصوص این موضوع وجود دارد).

**تورم:** رشدهای بنیادی اسمی‌اند. «گزارش مثبت» یعنی رشد بالاتر از آستانه ۳۰٪ (قابل تنظیم)، و شرکت زیان‌ده هیچ‌وقت «مثبت» حساب نمی‌شود.

**متن تحلیل:**
- **ساخت متن:** هر جمله فقط وقتی تولید می‌شود که داده پشت آن وجود داشته باشد.
- **جداسازی:** «مشاهده» و «تفسیر» جدا هستند.
- **واگرایی‌ها** به‌صورت احتمال بیان می‌شوند، نه قطعیت.
- **عبارات ممنوع** («قطعی»، «تضمین»، «بدون ریسک»، BUY/SELL، …) با یک فیلتر مسدود می‌شوند.

**اسکنر بازار:** 🔥 حجم غیرعادی · 💰 ورود پول حقیقی · 🟢 قدرت خریدار · 📈 کاندید شکست · 🔵 بهبود بنیادی · ⚠️ ریسک/واگرایی

## بک‌تست و مدل تصمیم

**بک‌تست:**
- **ورود:** در **اولین قیمت روز بعد** (نه قیمت پایانی‌ای که تازه دیده شده).
- **حذف‌ها:** روزهای قفل‌شده در صف خرید کنار گذاشته می‌شوند.
- **مقایسه:** نتیجه همیشه کنار **میانگین کل بازار** در همان دوره گزارش می‌شود.

**نمونه واقعی** (۲۰۱۹ تا ۲۰۲۶؛ حجم بیش از ۳ برابر، قدرت خریدار بالای ۲، ورود پول حقیقی، مومنتوم مثبت؛ ۳٬۲۰۲ مورد):

| افق | نرخ موفقیت الگو | نرخ موفقیت کل بازار | بازده اضافه |
|---|---|---|---|
| ۱ روز | ۳۳٪ | ۴۹٪ | −۰.۴٪ |
| ۱۰ روز | ۵۷٪ | ۵۲٪ | +۱.۲٪ |

یعنی خرید فردای چنین روزی معمولاً در روز اول ضرر می‌دهد و مزیت فقط در افق ۱۰ روزه دیده می‌شود. نتیجه در ۲۰۲۱ تا ۲۰۲۲ ضعیف بوده است.

**مدل LightGBM** برای دو هدف:
- رسیدن به ۳٪+ طی ۳ روز،
- بازده بیش از ۵٪ طی ۵ روز.

**تقسیم داده زمانی است:** آموزش ← calibration (۱۲ ماه) ← تست (۱۲ ماه آخر).

**نتیجه فعلی:**
- **رتبه‌بندی:** AUC حدود ۰.۵۵ تا ۰.۵۶. ده درصد بالای پیش‌بینی‌ها بهتر از میانگین عمل کرده‌اند.
- **Calibration:** رد شده. احتمال‌ها در سال آخر با واقعیت نمی‌خواندند.
- **پیامد:** ربات عدد احتمال نشان نمی‌دهد و فقط «Model Score» می‌نویسد. آستانه آزمون برای پاس شدن شل نشده است.

**JEV:**
- **وضعیت:** بررسی شد ولی اضافه نشده است.
- **دلیل:** فقط API خارجی و در دسترسی اولیه است، ورودی‌اش متن است، روی بازده بورس تهران calibrate نشده و بک‌تست آفلاین ندارد.
- **جای مناسبش:** دسته‌بندی متن اطلاعیه‌های کدال.
- **پیش‌نیاز:** کلید API و ارزیابی روی نمونه‌های برچسب‌خورده.

## نصب و اجرا (Windows)

پیش‌نیاز: [uv](https://docs.astral.sh/uv/). پایتون 3.14 و وابستگی‌ها را خودش نصب می‌کند.

```bat
copy .env.example .env        & rem اختیاری: آدرس Worker، توکن، پروکسی، PostgreSQL
start.bat                     & rem نصب، ساخت دیتابیس، اجرای scheduler + API محلی
```

بارگیری اولیه (یک بار):

```bat
uv run python -m bors_analyser snapshot          & rem فهرست نمادها + وضعیت فعلی بازار
uv run python -m bors_analyser backfill          & rem سابقه روزانه همه نمادها (~۱۵ دقیقه)
uv run python -m bors_analyser codal-bootstrap   & rem کدال (چند ساعت؛ قابل ادامه بعد از قطع شدن)
uv run python -m bors_analyser setups            & rem سابقه تاریخی الگوها
uv run python -m bors_analyser train             & rem آموزش مدل + آزمون calibration
```

دستورهای پرکاربرد:

```bat
uv run python -m bors_analyser analyze فولاد --mode swing --print
uv run python -m bors_analyser scan
uv run python -m bors_analyser backtest "volume_ratio_20>3, buyer_power>2" --start 2018-06-01
uv run python -m bors_analyser codal-parse --limit 100000
uv run python -m bors_analyser publish
uv run pytest
```

**زمان‌بندی** (به وقت تهران، شنبه تا چهارشنبه):

| ساعت | کار |
|---|---|
| هر ۲ دقیقه، ۸:۵۵ تا ۱۲:۳۵ | snapshot بازار |
| هر ۱۰ دقیقه | تحلیل کوتاه‌مدت |
| ۱۳:۲۰ | تحلیل کامل + اسکن + ارسال به Worker |
| ۱۹:۰۰ | سابقه رسمی روزانه |
| ۲۰:۰۰ | بک‌تست الگوها |
| هر ۱۵ دقیقه، هر روز | کدال |
| پنجشنبه ۱۰:۰۰ | آموزش دوباره مدل |

در شروع، scheduler کارهای جامانده (کدال، سابقه روزانه، تحلیل پایان روز) را جبران می‌کند. داده درون‌روزی ساعت‌هایی که سیستم خاموش بوده قابل بازیابی نیست.

**API محلی** (برای داشبورد آینده): `http://127.0.0.1:8008`

`/market` · `/stocks` · `/stock/{symbol}` · `/analysis/{symbol}?mode=` · `/signals` · `/tablo/{symbol}` · `/technical/{symbol}` · `/fundamental/{symbol}`

## ربات تلگرام (Cloudflare Worker)

**دستورها:** `/start` `/help` `/market` `/top` `/scan` `/stock نماد` `/tablo نماد` `/technical نماد` `/fundamental نماد`. خود نماد هم به‌تنهایی کار می‌کند.

**دستورهای مدیر:** `/stats` `/approve` `/block` `/unblock`

**امنیت:**
- **ورودی داده:** توکن Bearer با مقایسه زمان‌ثابت و اعتبارسنجی داده.
- **Webhook:** با هدر مخفی تلگرام بررسی می‌شود.
- **محدودیت‌ها:** محدودیت نرخ برای هر کاربر، و حالت اختیاری allowlist.
- **رمزها** فقط در `wrangler secret` نگه داشته می‌شوند.

مراحل استقرار: [worker/README.md](worker/README.md)
